# Release status — Firestore-only backend

Firebase Functions have been removed from the application, Firebase configuration and deployment scripts. All cloud reads/saves/restores now use direct Firestore transactions with Firebase Authentication and security rules. Shared domain validation lives in src/shared and is generated by npm run build:domain.

Frontend hosting is left to the user on Vercel. vercel.json sets the Vite build/output and cache headers. See FIREBASE_SETUP.md for environment variables and authorized-domain setup.

Verified:
- 59 regression tests pass.
- 7 direct-Firestore integration/security tests pass, including negative amounts, stale operations, closed periods, immutable audit records, restore/recovery and cross-user rejection.
- Authenticated browser test passes with only Auth/Firestore emulators: login, direct restore, bank match/unmatch, closing, linked reversal, reload and report balance.
- No firebase/functions or httpsCallable dependency remains in active app/test/configuration paths.

Rules enforce the key access and record protections. Cross-record uniqueness, full date validation and aggregate calculations also rely on the shared application validator; see FIREBASE_SETUP.md for the trust boundary and bulk-restore limits.

The earlier Functions/Blaze deployment blocker no longer applies to this architecture. This does not remove Firebase Spark quotas or guarantee unlimited free usage. Live frontend sign-in and saves must be checked after the user publishes the Vercel build.

Deployment confirmed: Firestore rules and indexes were successfully released to robins-e3132. Firebase Hosting was not deployed. Publish the updated frontend to Vercel with the Firebase web configuration and add the Vercel domain to Firebase Authentication's authorized domains.
